# TaktGrid — ERP-матрица производственного планирования

Портфолио-проект по ТЗ (см. `TaktGrid-TZ.md`, отдельный документ). Дизайн — по референсам дашборда и матрицы планирования.

## Запуск

```bash
npm install
npm run dev       # http://localhost:5173
```

Бэкенда нет — весь API замокан через MSW (`src/app/mocks`), данные генерируются на лету через `@faker-js/faker` с фиксированным seed (воспроизводимо между запусками).

```bash
npm run build       # tsc -b && vite build — прод-сборка
npm run test         # vitest run — юнит-тесты
npx steiger ./src     # архитектурный линтер FSD 2.1 — 0 ошибок
npx oxlint src        # быстрый линт — 0 ошибок/предупреждений
```

## Статус: все разделы ТЗ реализованы

### Дашборд (`/`)
KPI-карточки, тепловая карта загрузки по группам станков, донат распределения, таблица "заказы, требующие внимания" (клик → сразу нужный момент в матрице), мини-гант на сегодня с линией "сейчас", быстрые фильтры, графики план/факт выпуска и простоев по причинам.

### Матрица планирования (`/matrix`) — ядро проекта
- Двухосевая виртуализация: вертикаль — `@tanstack/react-virtual`; горизонталь (365×24 часа) — без поячеечного DOM, линии часов CSS-паттерном, блоки позиционируются напрямую по timestamp → px
- Sticky-шапка/колонка через синхронный скролл трёх контейнеров
- Zoom Час/День/Неделя, "Сегодня", windowed-подгрузка назначений при скролле
- **Drag-перенос блока между станками** — Pointer Events + `setPointerCapture`, живая валидация занятости, серверная проверка (409 при конфликте), transient-уведомление об ошибке
- **Выделение диапазона** ячеек drag'ом + живая сводка (машино-часы, заказы, статусы)
- **Bulk Edit** — относительное/абсолютное изменение плана, округление по кратности упаковки, live-предпросмотр "было → станет"
- **Мастер заказа** — динамическая форма: выбор продукта → авто-техкарта, live-расчёт машино-часов (`useDeferredValue` на количестве/сроке, чтобы не блокировать ввод), поиск свободных слотов по всем станкам группы, ghost-превью прямо в матрице, feasibility-индикатор (укладывается/впритык/не укладывается)
- **Фильтры тулбара** — по цеху/статусу/приоритету, реально фильтруют строки/гасят несовпадающие блоки
- **Мини-карта** — обзор годового диапазона, клик = прыжок к моменту
- `OccupancyIndex` (бинарный поиск пересечений интервалов) и `findFirstAvailableSlot` — алгоритмическое ядро, покрыто юнит-тестами, используется одинаково и в рендере блоков, и в drag-валидации, и в мастере заказа

### Периферийные страницы — все рабочие, не заглушки
- **Заказы** — поиск, фильтры по статусу/приоритету, пагинация
- **Станки и оборудование** — таблица + боковая панель: история простоев, форма добавления ТО (реальный POST)
- **Продукция и техкарты** — таблица + редактирование темпа/кратности (реальный PATCH)
- **Конфликты** — реально вычисленные пересечения простоев с назначениями + заказы под угрозой, переход прямо к моменту в матрице
- **Аналитика** — период 7/30/90 дней, графики загрузки/выпуска/простоев (общий виджет `widgets/trend-charts`, переиспользуется с дашбордом), реальный CSV-экспорт
- **Календарь** — месячная сетка, счётчики заказов по дням (клик → матрица), отметка выходных
- **Настройки** — рабочий календарь, пороги уведомлений, роли (состояние в рамках сессии — честно указано в самом интерфейсе)

## Архитектура

- **FSD 2.1** (`app/pages/widgets/entities/shared`), **Steiger** в CI-режиме — 0 нарушений
- **MobX** — точечная реактивность UI-состояния грида (`GridStore`: зум, выделение, drag/preview-призраки, фильтры, видимый диапазон)
- **Zustand** — локальный UI-стейт виджетов (`useSidebarStore`)
- **React Query** — весь сетевой слой и кэш, включая оптимистичные инвалидации после мутаций
- **React Hook Form + Zod** — валидация формы мастера заказа
- Виджет `widgets/trend-charts` — пример намеренного рефакторинга "pages first → extract on reuse" (см. ТЗ п.2): появился, когда графики понадобились и дашборду, и аналитике

## Известные упрощения мок-слоя

- `useOrdersQuery` в матрице тянет весь датасет разом — в проде это был бы постраничный запрос
- Правила простоя генерируются независимо от назначений — пересечения не реконсилированы заранее (это контент для страницы "Конфликты", а не баг)
- Настройки не персистентны между перезагрузками страницы
- Датасет: 4 цеха, 7 групп станков, 2 станка на группу (~14 станков), разреженный график — по несколько заказов в день на станок, seed 42
- Авторизация — мок с единственным демо-пользователем admin/admin (см. `entities/session`), без реального бэкенда
